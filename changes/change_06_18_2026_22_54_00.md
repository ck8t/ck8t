## 3 — Logical Block Branch Labels (if_else / if_elseif_else / switch)

**Before:** Branch output handles showed raw IDs (`branch_1`, `case_1`, `case_2`) — verbose and inconsistent with the block's logical meaning.

**After:** `formatHandleLabel()` maps to cleaner display names:
- `branch_1` → `if`
- `branch_N` (N > 1) → `elif N`
- `case_N` → just `N`
- `true`, `false`, `else`, `default` → unchanged (already clean)

Also improved CSS:
- `bs-port-strip-branch`: Added `border-top` separator, refined padding
- `bs-port-branch-label`: Uppercase font, `flex: 1`, right-aligned text
- Colors: slightly more saturated for better contrast (purple for case, red/green for true/false)
- Removed `padding-right: 56px` from `bs-node-multi-out` (was a legacy rail offset that pushed labels away from handles)

**Files:** `src/ck8t/canvas/WorkflowNode.jsx`, `src/ck8t/ck8t.css`

## 4 — Code/Code-Editor SubBlock Type Now Renders in Node Cards

**Before:** SubBlocks with `type: 'code'` or `type: 'code-editor'` (e.g. if_else's `expression` field) hit the `default: return null` case in `renderFieldControl` → showed nothing in the card body. The `INLINE_INTERACTIVE` / `INLINE_EDITABLE` sets also excluded these types so they showed as read-only with `formatPreview`.

**After:**
- Added `case 'code':` and `case 'code-editor':` to `renderFieldControl` — renders as `InlineInput` (single-line text, full Monaco in Inspector)
- Added both types to `INLINE_INTERACTIVE` (and by extension `INLINE_EDITABLE`)
- Added `'code-editor'` to `fieldPinColor` — blue color dot (same as other string fields)

**Effect:** `if_else` now shows the `Condition` expression inline in the card. `slave_agent` output schema shows inline. All code fields are now editable directly on the canvas node card.

**Files:** `src/ck8t/canvas/WorkflowNode.jsx`

## 5 — TypeError: e is not iterable (Copilot error)

This error in VS Code Copilot's `extension.js` at `D3e.setItems` is **not caused by our code**. It originates entirely within VS Code's Copilot extension (vscode-app/.../copilot/dist/extension.js) during extension initialization triggered by a `setTimeout`. This is a Copilot bug that occurs independently of the CK8T extension.
