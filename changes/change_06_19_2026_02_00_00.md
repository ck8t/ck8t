### What was built

**BlockDebuggerPopup layout:**
- Header: BugIcon + "Debugger — {title}" + inline VS Code-style HUD toolbar + status chip + close
- HUD: grip handle · Run · Continue · Step Over · Step Into · Step Out · Restart · Stop · Mute Breakpoints (all with Daakia SVG icons)
- File tabs: one per block file, active/paused highlight, breakpoint count badge
- Body two-column: left = Monaco EditorView (debugSupported, breakpoints, pausedLine, glyph context menu) | right = 290px Run and Debug panel
- Right panel sections (Daakia CollapsibleSection style with accent colors):
  - VARIABLES (scope groups: Local, Block Inputs; recursive ValueNode tree; Daakia-style #4fc3f7 name color)
  - WATCH (add expression, live evaluate from variables, remove per row)
  - CALL STACK (frame list with active-frame highlight, paused badge)
  - BREAKPOINTS (checkbox enable/disable, dot color by type, remove, navigate-to-line)
  - Test Input textarea + Output/Error pre block
  - CONSOLE (log/info/warn/error/debug with level colors)

**Glyph context menu (Daakia-style):**
- Add Breakpoint, Remove Breakpoint, Disable/Enable Breakpoint, Edit Condition…, Add Conditional Breakpoint…
- Conditional breakpoint inline input overlay (positioned at breakpoint line)

**BlockDebugEngine changes:**
- Variable capture: scans declared var/let/const names before each breakpoint, passes as `{ varName: typeof varName !== 'undefined' ? varName : undefined }`
- Always includes `input` and `values` in variable list
- `stepInto()` and `stepOut()` added (both resume for now)

**block-debugger-store changes:**
- Added: variables, callStack, disabledBreakpoints, conditions, breakpointsMuted, navigateLine, navigateFile
- Added actions: addConditionalBreakpoint, toggleDisableBreakpoint, removeBreakpoint, clearAllBreakpoints, toggleMuteBreakpoints, setNavigateLine, clearNavigate
- `setPaused()` merges variables IntelliJ-style: update existing, add new, never remove
