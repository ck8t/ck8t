# Change: Block Debugger — execute through canvas Run, fix crash, float the HUD
**Date:** June 20, 2026

## What changed

The previous debugger tab (`change_06_19_2026_07_00_00.md`) shipped with a standalone
"Run block" button and a sticky HUD bar — neither matched the requirement: debugging
should ride the same canvas Run button that already executes blocks, Daakia-style
(same Send button, backend decides whether to route through the debugger based on
whether breakpoints exist).

### Canvas Run now auto-routes through the debugger

- **`src/ck8t/run/graph-runner.js`** — `runNode()` now calls `getActiveDebugRun(nodeId, blockType)`
  before invoking the normal runner. If the Debugger tab has this exact node open with
  live (non-muted, non-disabled) breakpoints on its browser-executable file (`client.js`
  for normal blocks, the function block's own code for `function`), the run is routed
  through a new `BlockDebugEngine` instance via `runThroughDebugger()` instead of calling
  the runner directly — using the *same* `ctx` `buildRunCtx()` already builds. No
  breakpoints → normal execution, unchanged.
- **`src/ck8t/debug/block-debugger-store.js`** — added `engine`/`setEngine()` so the panel's
  Continue/Step/Stop buttons can drive the engine instance graph-runner.js creates, and
  `lastDebugRun`/`setLastDebugRun()` so Restart can replay the last canvas-triggered run
  without re-running the whole workflow.

### Removed: "Run block" button and all standalone/extension-side execution

- **`src/ck8t/debug/BlockDebuggerPanel.jsx`** — removed `handleRunDebug`, the Test Input
  section, and the `isExtension` branches in every control handler. Continue/Step
  Over/Step Into/Step Out/Stop now read `useBlockDebuggerStore.getState().engine`
  directly. Restart replays `lastDebugRun` through a fresh engine.
- **`extension/vscode/ck8t/src/panel/Ck8tPanel.ts`** — deleted `_runBlockDebugExtension`,
  `_transformForDebug`, `_isExecutableLine`, the `_blockDebugResumeResolve`/
  `_blockDebugStopped` fields, and the `blockDebug:runExtension`/`resume`/`stepOver`/`stop`
  message cases — all dead now that execution always happens in the webview/browser, same
  as the canvas Run button. `blockDebug:getFiles` (source fetch for the editor tabs) is kept.
- Deleted the now-fully-unused `src/ck8t/debug/BlockDebuggerPopup.jsx` (superseded by
  `BlockDebuggerPanel.jsx` in the prior change, but never removed).

### Fixed: "Unexpected token '{'" crash (the real root cause this time)

The actual bug: `transformForDebug` injected a breakpoint-pause statement before *any*
breakpointed line, including object-literal property lines like `type: 'text_template',`
that sit outside the `run()` method body — producing invalid syntax mid-object-literal.

- **`src/ck8t/debug/block-debug-engine.js`** — rewritten with two modes:
  - `'module'` (community/core `client.js` runner files): `findRunBodyRange()` locates the
    matching `type:` entry's `run()` method body via brace-depth tracking, and
    `injectModuleBreakpoints()` only injects pause calls for brace-depth-0 statements
    *inside* that body — breakpoints outside it (object-literal lines, etc.) are now
    silently no-ops instead of crashing. Executes `entry.run(ctx)` with the real ctx.
  - `'script'` (function block's raw `values.code`): same brace-depth-0 injection at the
    top level of the flat script — unchanged behavior, renamed `injectFlatBreakpoints`.
  - Also fixed two latent bugs found while testing against `text_template/runners/client.js`:
    1. `preprocessCode()`'s import/export-stripping regexes used `\s*` before `$`, which can
       swallow the line's own trailing newline when followed by a blank line — silently
       shifting every later line number by one and breaking breakpoint↔source-line
       alignment. Now uses `[ \t]` (never `\n`-matching `\s`) so line count is always exactly
       preserved.
    2. A breakpoint set on the same line as a `const`/`let` declaration captured that
       variable in its own pause snapshot — a TDZ violation that threw "Cannot access 'x'
       before initialization". Declarations are now recorded *after* the breakpoint check,
       not before, so a paused line only sees variables declared by *earlier* lines.
  - `run()` now returns the real output / throws the real error (tagged `isDebugStop` for a
    deliberate Stop) so graph-runner.js can treat a debug-driven run exactly like a normal
    one downstream.

### Floating HUD (Daakia-style)

- **`src/ck8t/debug/BlockDebuggerPopup.css`** — added `.bdp-float-hud` /
  `.bdp-float-hud-grip`: `position: absolute; top: 8px; left: 50%; transform:
  translateX(-50%)`, backdrop-blur, box-shadow, entrance animation — anchored to
  `.bdp-panel` (now `position: relative`) instead of living inside the sticky
  `.bdp-header` bar. Only rendered while a debug session is running/paused. Removed the
  now-dead `.bdp-hud`/`.bdp-hud-grip`/`.bdp-hud-btn-run`/`.bdp-hud-label` rules and the
  Test Input CSS.

## Build
`npm run vscode` ✓ clean (twice — once before, once after deleting the dead popup file)

## Manual verification
Ran the new engine directly against `src/ck8t/blocks/text_template/runners/client.js`
(the exact file from the original bug report) via a standalone Node script:
- Breakpoint on the `type:` line (outside `run()`) → completes normally, no crash.
- Breakpoint on a `const` line inside `run()` → pauses, captured vars correct, resumes,
  completes.
- Breakpoint on the `return` line → pauses with all locals visible, resumes, completes.
- `function` block script mode → pauses, console capture works, resumes, completes.
- Stop while paused → throws a tagged `isDebugStop` error, not a generic crash.
