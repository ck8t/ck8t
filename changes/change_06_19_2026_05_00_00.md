# Change Log — June 19, 2026 05:00

## Core Block Runner Refactor (Sprint 6.7)

### Summary
All core blocks now follow the exact same isolated runner contract as community blocks: `export default [{ type, run(ctx) }]`. The `graph-runner.js` 700-line switch statement is replaced with a registry lookup + `buildRunCtx()` context injection. No block logic lives in `graph-runner.js` anymore.

### New contract
```js
// ctx contains: values, input, inputsByHandle, outputs, node, nodeId, nodeTitle,
//               subBlockValues, allNodes, callTool, callAgent, callLlm,
//               resolveModel, getSkill, runSkill, vsApi, progress
export default [{ type: 'my_block', async run(ctx) { ... } }]
```

### New files
- `src/ck8t/blocks/block-utils.js` — shared pure utilities (jsonPath, interpolateBag, evalSafe, safeJson, arrayBufferToBase64, extractMediaUri, extractImageUrl)
- `src/ck8t/blocks/core-block-runners.js` — imports all individual block runners, builds `coreBlockRunners` Map
- `src/ck8t/blocks/*/runners/client.js` — isolated runner for every core block (50+ files)

### Updated files
- `src/ck8t/blocks/registry.js` — re-exports `coreBlockRunners` from `core-block-runners.js`
- `src/ck8t/run/graph-runner.js` — `runNode()` replaced with registry lookup + `buildRunCtx()`; removed old 3 named runner imports; added `buildRunCtx()` function
- `extension/vscode/ck8t/src/engine/graph-runner.ts` — updated `require()` calls for extension.js files to use new `export default [...]` format

### Architecture
- Community blocks: `customBrowserBlockRunners` Map (unchanged)
- Core blocks: `coreBlockRunners` Map (new)
- Graph runner: `runner = coreBlockRunners.get(type) ?? customBrowserBlockRunners.get(type)` then `runner(buildRunCtx(...))`
- Extension blocks (chain_of_thought, slave_agent, master_agent): client.js re-exports extension.js via `export { default } from './extension.js'`
