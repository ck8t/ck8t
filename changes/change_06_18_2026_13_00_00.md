# Change — 06/18/2026 13:00:00

## Summary

Fixed two runtime type errors in the Getting Started workflow library that caused W01 and W16 to crash on first run.

## Root Cause

The CK8T runtime validates edge type compatibility before passing data across connections. Two blocks have `inputs.input: { type: 'json' }` as a **declared** typed port — meaning the runtime rejects plain strings at the edge level:

- `text_template.inputs.input` → type `json` (requires a JSON object with `{{field}}` keys)
- `switch_case.inputs.input` → type `json` (the `keyExpr` expression evaluates against this object)

Both W01 and W16 were wiring `user_input.value` (type `any`, runtime string) directly into these json-typed ports, causing:

```
Runtime type error: "Your Name" → "Greeting": expected json object, got string
```

## Fixes

### W01 — Hello World (user_input + text_template)

**Before:** `starter → user_input → text_template → show_preview`  
**After:** `starter → user_input → function (Wrap) → text_template → show_preview`

- Added function node `g1_fn` between user_input and text_template
- Function code: `return { name: input || "World" }` — wraps the string into a JSON object
- `user_input.value → function.in_input` (dynamic port, accepts any)
- `function.result → text_template.in_input` (JSON object ✓)
- Updated text_template to use `{{name}}` instead of `{{input}}`
- Node column positions shifted: function at col 2, text_template at col 3, show_preview at col 4

### W16 — Switch Router (switch)

**Before:** `starter → user_input → switch → text_templates`  
**After:** `starter → user_input → function (Wrap) → switch → text_templates`

- Added function node `gg_fn` between user_input and switch_case
- Function code: `return { category: input }` — wraps the string into a JSON object
- `user_input.value → function.in_input` (dynamic port, accepts any)
- `function.result → switch.in_input` (JSON object ✓)
- Updated switch `keyExpr` from `'input'` to `'input.category'` to match the wrapped structure
- Node column positions shifted: function at col 2, switch at col 3, text_templates at col 4

## Why Other Workflows Are Not Affected

The audit of all 45 workflows confirmed only these two had the type mismatch:

- **Agent blocks** (`user_input.value → agent.in_input`): Agent has **no declared `input` port**, so `in_input` is a dynamic port that accepts any type. Agent's `userPrompt` template `{{input}}` resolves from the dynamic execution context.
- **Function blocks** (`user_input.value → function.in_input`): Same — function has no declared `input`, dynamic port, code uses `input` as an injected variable.
- **if_else / if_elseif_else** (W15, W19): These receive `function.result` (JSON object), not a raw string.
- **chain_of_thought** (W12): Uses `in_question` port, declared as `type: 'string'` ✓
- **crypto** (W29): Uses `in_data` port, declared as `type: 'string'` ✓
- **ai_classifier** (W17): Uses `in_text`, declared as `type: 'string'` ✓
- **master_agent** (W43): Uses `in_question`, declared as `type: 'string'` ✓
- **mcp** (W45): Uses `in_input`, declared as `type: 'any'` ✓
