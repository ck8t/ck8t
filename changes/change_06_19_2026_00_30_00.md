# Change — 06/19/2026 00:30:00

## Summary

Replaced all duplicated inline orchestration block runner logic (chain_of_thought, slave_agent, master_agent) in both graph-runner files with delegates to the canonical block runner JS files. Also enhanced `loadInstalledBlocks()` to auto-register client-side runners from `ck8t-block.json` manifests.

## Step 4 — extension graph-runner.ts: delegate to block runners via require()

**Before:** `extension/vscode/ck8t/src/engine/graph-runner.ts` had ~170 lines of inline TypeScript functions duplicating the orchestration logic:
- `runChainOfThoughtNode` (lines 515–540)
- `runSlaveAgentNode` (lines 542–568)
- `topoSortSteps` + `MasterCotStep` interface + `runMasterAgentNode` (lines 570–682)

**After:**
- Added `require()` imports at the top of the file pointing to the canonical block runner JS files. esbuild (not tsc) bundles these at build time — the tsconfig `rootDir` restriction does not apply.
- Switch cases now call `_runCot`, `_runSlave`, `_runMaster` with the correct typed arguments.
- All inline TypeScript duplicates deleted.

**Files:** `extension/vscode/ck8t/src/engine/graph-runner.ts`

## Step 5 — client graph-runner.js: delegate to block runners via ES imports

**Before:** `src/ck8t/run/graph-runner.js` had ~120 lines of inline functions duplicating orchestration logic:
- `runChainOfThoughtNode`, `runSlaveAgentNode`, `_topoSortSteps`, `runMasterAgentNode`

**After:**
- Added ES `import { run as _runCot/Slave/Master }` from the block runner files at the top.
- Added `_makeCallAgent(nodeTitle)` adapter that bridges `callLlmWithFallback(agent, str, title)` to the `callAgent({ agent, input }) → { output }` interface expected by block runners.
- Switch cases resolve the model from `useLlmConfigStore` (injecting it into `values` so the block runner doesn't throw on missing model), then call the block runner with the `_makeCallAgent` adapter.
- All inline JS duplicates deleted.

**Files:** `src/ck8t/run/graph-runner.js`

## Step 7 — loadInstalledBlocks: self-register client runners from ck8t-block.json

**Before:** `loadInstalledBlocks()` dynamically imported block UI files but never loaded or registered browser-side runners from the manifest.

**After:** After importing the UI file for each block, the function now checks:
1. `blockEntry.clientRunner` — per-block runner path in the manifest
2. `manifest.runners.client` — package-level fallback runner path

If found, dynamically imports the runner from the block-manager URL and registers it via `customBrowserBlockRunners.set(blockEntry.type, runFn)`. The runner must export `run` or `default.run`.

**Files:** `src/ck8t/blocks/registry.js`
