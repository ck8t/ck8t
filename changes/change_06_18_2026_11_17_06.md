# Change — 06/18/2026 11:17:06

## Summary

Complete revamp of Workflows, Teams, Agents, and Skills hierarchy. Workflows now live in expandable folders (with a "Getting Started" folder seeded by default). Each workflow can belong to multiple teams. The Teams panel now shows a Team → Agents tree instead of a flat list. The Agents panel retains the pool-based tree for power users.

## Changes

### New: `workflowFolders[]` data model (workspace-store.js)
- Added `workflowFolders: [{ id, name }]` to store state — seeded with `folder_getting_started / Getting Started`
- Workflows now have `folderId: string|null` and `teamIds: string[]` (alongside legacy `teamId` for backward compat)
- Added `createWorkflowFolder`, `renameWorkflowFolder`, `deleteWorkflowFolder` store actions
- Updated `createWorkflow(name, teamIds, partial)` — accepts array or single string (backward compat)
- Updated `importWorkflow(name, teamIds, { ..., folderId })` — same compat
- Version bump 8→9 with migration that adds `workflowFolders` and normalizes `teamId → teamIds[]` on existing data
- Fixed undefined `seedAgent1Id`/`seedAgent2Id`/`seedSkillId` variables in `merge` function

### New: Folder tree WorkflowsPanel (SideNav.jsx)
- `WorkflowsPanel` rewritten as an expandable folder tree
- Folders expand/collapse with chevron; double-click to rename inline
- "+ New Folder" / "+ New Workflow" buttons at the top
- Context menus on both folders and workflows (open, rename, duplicate, delete)
- New folder name entered via inline input (blur or Enter to confirm)
- Deleting a folder moves its workflows to root (not deleted)
- Root-level workflows (no folder) shown below folders

### New: Team → Agents tree TeamsPanel (SideNav.jsx)
- `TeamsPanel` rewritten to show a collapsible Team → Agents tree
- Each team shows all its agents (flattened across pools — pool is now an implementation detail)
- Agent rows show model + skill count as meta
- "+ Add agent" row at bottom of each expanded team; auto-creates "Default Pool" if none exists
- Context menus on teams and agents
- Teams show "N agents" count instead of "N pools"

### Updated: CreateWorkflowModal.jsx
- Replaced single team StyledSelect with a checkbox list (multi-team selection)
- Added folder picker (StyledSelect from `folders` prop, defaults to first folder)
- `onCreate(name, teamIds[], folderId)` callback

### Updated: ImportWorkflowModal.jsx
- Same changes as CreateWorkflowModal
- `onImport(name, teamIds[], folderId)` callback

### Updated: WorkflowInspector.jsx (panel)
- Team field replaced with checkbox list (multi-team)
- `updateWorkflow` patches both `teamIds[]` and `teamId` (first item, for compat)
- Removed unused `StyledSelect` import

### Updated: TeamEditor.jsx
- Workflow filter now checks both `w.teamIds.includes(teamId)` and legacy `w.teamId === teamId`

### Updated callers
- `AgentBuilderPage.jsx` — `onCreate(name, teamIds, folderId)` + added `workflowFolders` store selector
- `Canvas.jsx` — `handleJsonDropConfirm(name, teamIds, folderId)` + export includes `teamIds`/`folderId` + added `workflowFolders` store selector

### New CSS (ck8t.css)
- `.bs-sec-actions` — two-button action row at top of panel
- `.bs-add-btn-sm` — compact variant of add button
- `.bs-empty-sm` — smaller empty state for nested lists
- `.bs-row-indent` — 16px spacer for indented workflow rows
- `.bs-add-inline` — "Add agent" row at bottom of expanded team
- `.bs-link` — inline link-style button
- `.bs-label-hint` — muted hint text in form labels
- `.bs-inline-form-sm` — compact inline form variant
- `.bs-checkbox-list` — vertical checkbox list layout
