# Change Log — June 19, 2026 03:00

## Block Debugger: Mini-tile, Empty State, Icon/Color Propagation

### Files Changed

- `src/ck8t/debug/block-debugger-store.js`
  - `setFiles()` now sets `filesStatus: 'loaded'` when files arrive (including empty array)
  - Prevents user_input and no-runner blocks from showing "Loading files…" forever

- `src/ck8t/canvas/WorkflowNode.jsx`
  - `openDebugger` call now passes `Icon` (block icon component) and `cfg?.bgColor || data?.bgColor` as 4th/5th args
  - Enables block mini-tile to render correct icon and background color in debugger

- `src/ck8t/debug/BlockDebuggerPopup.jsx`
  - Destructures `blockIcon`, `blockBgColor`, `filesStatus` from store
  - Added `.bdp-block-tile` header strip above the HUD: colored icon well + block title + monospace type chip
  - "Loading files…" now conditionally shows "No debuggable files for this block type." when `filesStatus === 'loaded'` and files array is empty

- `src/ck8t/debug/BlockDebuggerPopup.css`
  - Added `.bdp-block-tile`, `.bdp-block-icon-well`, `.bdp-block-tile-title`, `.bdp-block-type-chip` styles
  - Mini-tile sits between modal top and HUD header, showing block identity at a glance

### Why
- user_input block has no `runners` in manifest → extension returns empty files → was stuck at "Loading files…"
- Block mini-tile requested by user (screenshot reference) to know which block is being debugged
- Icon/color passed from WorkflowNode where cfg and data are in scope
